## What changed

### Feature-local time awareness (`lib/features/common/deadline_clock.dart`)

- `DeadlineClock` — a single clock seam (`overrideNow` for tests, real clock in production).
  Screens no longer read `DateTime.now()` during builds; `grep -rn "DateTime.now" lib/features`
  finds only this seam and parameter names.
- `DeadlineTicker` — one per mounted screen, a `ChangeNotifier` + `WidgetsBindingObserver`:
  - `watch(instants)` registers every instant at which visible deadline state can change and
    keeps **one** timer for the earliest one. No polling, no per-second tick.
  - `deadlineWatchInstants(jobs, now)` yields each deadline, each deadline's three-day
    "closing soon" start, and the next IST midnight (for relative "posted …" labels).
  - On app resume it cancels the timer, re-reads the clock and notifies immediately, covering a
    suspended process that slept through its timer.
  - `dispose()` cancels the timer, removes the lifecycle observer and decrements a debug counter
    (`DeadlineTicker.debugLiveTickers`) used by the leak test.
- Wired into `HomeScreen` (cards, closing-soon filter, counts, notification sheet clock),
  `JobDetailScreen` (status pill, closed banner, reminder availability),
  `SavedScreen` and `CalendarScreen` (Upcoming/All split, month headings).
  Constructors and shared contracts are unchanged.

### Deadline semantics preserved

Date-only deadlines still close at **00:00 IST of the next day** (exclusive boundary); an exact
`application_end_at` still closes at that instant; withdrawn still wins; no-deadline jobs still
refuse reminders. The ticker only re-evaluates those existing rules with a fresh clock.

### Permission dialog outliving the deadline

`setReminderIntent` now accepts optional `deadlineAt(now)` and `now` seams. Permission is still
requested first, but after it returns the deadline is **recomputed** and an enable intent is
written only if the job is still open. A dialog that stays open past the deadline therefore yields
`ReminderOutcome.closed` and **no** preference write. Disabling an existing intent is unchanged and
needs neither permission nor a live deadline. Detail passes the live clock, not a build snapshot.

### Bengali app name

`K.appName` and the Bengali disclaimer now read **কর্মপথ** (was কার্মপথ). No other spelling of the
old form remains in `lib/features`.

## Notes for captain

1. Ticker intervals are event-driven, not periodic: a screen with only far-future deadlines wakes at
   the three-day window, at the deadline, and at each IST midnight.
2. If the app shell later exposes an app-wide clock (e.g. for the production shell), it can replace
   `DeadlineClock.overrideNow` semantics; screens need no change beyond the provider.
3. The notification sheet reads the ticker clock when opened; it does not tick while open (a modal
   sheet is short-lived). Calendar/detail/cards all tick.
4. No new dependencies, no shared-surface edits, no app composition changes.
