## What changed

### 1. District and qualification filters (Home)

- New top-level helpers `availableDistricts(jobs)` / `availableQualifications(jobs)` build the
  sorted, de-duplicated option lists from the **current feed only**.
- Two new chips in the existing horizontal filter row (`জেলা` / `যোগ্যতা`), each showing a
  selected count (`জেলা · ২`). They open a scrollable bottom sheet of `HomeFilterChip`s with an
  "all districts / all qualifications" reset and a Done action.
- Semantics: **OR within a facet** (Kolkata or Howrah), **AND across facets** and AND-combined with
  the existing query, category, kind and closing-soon filters.
- Clear-all (`ফিল্টার মুছুন`) now also resets both facet sets; it still clears search, category,
  kind and closing-soon.
- A repository listener prunes selections that no longer exist after a refresh, so a stale pick
  cannot silently hide the whole feed. Empty facets hide their chips instead of showing an empty
  sheet.
- Approved v2 layout is unchanged: same hero, palette, category strip, card design and compact
  spacing. The only visual additions are two chips in the existing row.

### 2. Truthful bookmark / remove failure feedback

- `JobCard`'s bookmark is now a stateful guarded button: a rejected write shows
  `K.saveFailed` / `K.removeFailed` in the current language, the stored state stays unchanged, and
  taps are ignored while a write is in flight, so a rapid double tap cannot show a success the
  store never confirmed.
- `SavedScreen` now tracks pending removals: the unavailable-tile "remove" action is disabled while
  writing, and a failure keeps the tile with `K.removeFailed` — no silent swallow.
- `JobDetailScreen`'s bookmark reports saving/removal copy (previously it reported
  `K.reminderFailedMsg`, i.e. reminder wording for a save error) and is guarded the same way.
- New copy is distinct from reminder copy in both languages; a test asserts all five messages
  (save / remove / reminder failed / reminder denied / no deadline) are distinct.

### 3. Calendar stale/offline indication

`CalendarScreen` now renders `OfflineBanner` when `isOffline` with a cached feed, and the stale
variant when a refresh failed but a cache exists, matching Home and Saved. Live feeds show no
banner.

### 4. 320px / 2x text accessibility

`test/features/accessibility_320_test.dart` renders all five screens at 320×720 with
`TextScaler.linear(2.0)`, long Bengali and English titles/summaries, the notification sheet, and
scrolls each screen end to end. Real defects found and fixed (not test tweaks):

| Defect found at 2x / 320px | Fix |
|---|---|
| Facet sheet overflowed 1.6px (Column of fixed rows) | whole sheet is a `SingleChildScrollView` |
| Calendar scope filter overflowed 9.5px right | `Row` → `Wrap` so segments stack |
| Settings card header overflowed 156px right | title wrapped in `Expanded` |
| Detail disclaimer header overflowed 110px right | label wrapped in `Expanded` |
| Filter chips/segments were 38–40dp tall | all pill/segment targets now ≥48dp |
| White small text on brand coral (3.1:1) | text-bearing coral uses `KPalette.coralStrong` (white 5.8:1) |

Contrast is asserted numerically (`KPalette.contrastRatio`) rather than by eye: white on
`coralStrong` ≥ 4.5, brand coral + white < 4.5 (documented reason for the darker token), ink on brand
coral ≥ 4.5. The darkened tone is feature-local (`lib/features/common/palette.dart`) — the shared
theme, fonts and assets were not touched.
